Commit validation and full certification

From the repository root, run:

    npm run check:commit

The npm command invokes the same bootstrap Git uses for an ordinary commit.
Stage the intended changes first. Unstaged and untracked development
can continue during validation. Changing the staged tree, HEAD commit, or HEAD
branch invalidates the result and requires another run. A standalone successful
run is diagnostic evidence; it is never a reusable commit authorization.

The developer-controlled hook copies the active index (including Git's temporary
index for partial commits), computes its tree through that private copy, and
checks the tree against HEAD for whitespace errors and conflict markers. It
loads the snapshot coordinator from that tree without consulting the working-tree
package scripts. The coordinator verifies the captured tree and HEAD still match
the bootstrap, then runs the staged validator and its dependencies in a private
checkout of that tree. Validation runs alongside edits in the developer's
working directory.
Final verification also uses a fresh private index copy; neither tree calculation
acquires or updates the developer's index, so concurrent invocations do not
compete for its lock. The private candidate/final index files remain with reports.
The checkout shares Git objects for reading, with its own index and refs.
Checkout attributes disable smudge filters, EOL/encoding conversion and ident
expansion so tools read the exact staged blobs, including export-ignore files.
Tracked symlinks and submodules are rejected before executing candidate stages.
Repositories without an initial HEAD commit and conflicted indexes are rejected.

Root and editor npm ci installs are independently attempted inside each checkout;
node_modules, dist, and .hson are never linked to the developer's copies. npm's
normal download cache may be shared. Fresh installs can require network access
and add time. If the root install fails, the gate records inventory as unexecuted
and blocks its commands. The commit gate can still run root checks after an
editor-only setup failure, which blocks editor typing and fails the gate.

The commit gate runs inventory and source-pin preflight, the root build, source,
test, tooling and editor typechecks, and public entrypoint typechecks. Three
regressions cover Hson document semantics, rejection of portable node identity
claims, and built public entrypoint imports and shared runtime identity.
Independent stages continue after validation failures. Test typing, public
entrypoint typing and built entrypoint runtime checks require a successful root
build even when inventory cannot load. When discovery produces an inventory that
fails integrity checks, the ledger records the failure and retains its dependency
information.

Run full certification against a committed revision from the repository root:

    npm run check:full

This captures the current HEAD commit and tree and uses their files and lockfiles
in a private checkout. The full sequence, inventory checks, ordinary fail-fast
behavior, and continue-on-failure behavior for the additional stages are
preserved. Dependency setup failure blocks certification. The three approved
build-reuse wrappers retain their source, artifact and compiler-dependency guards.
Cancellation and incomplete process cleanup stop further launches in either gate.

The commit result applies to the staged gate only. The existing working-directory
commands npm run check and npm run check:extended retain their original
selections, including the separate extended environments.

Reports are printed at startup and completion and retained under:

    $(git rev-parse --git-common-dir)/validation-reports/<unique-run>/

candidate.json records the candidate tree, initial/final HEAD and branch, final
index tree, outcome, cleanup, and setup/gate report locations. certification.json
records the fixed commit and tree alongside the outcome and ledger locations.
Stage ledgers record status counts, dependency blockers, commands, timings, and
failure categories where supported by test and process evidence. The case ledger
identifies started cases left unfinished and planned cases never reached. For
suites without a case plan, the unreached case list is unknown. Stage stdout and stderr
are captured together without truncation in numbered .log files beside each
stage ledger. External report artifact paths are relative to that ledger's
directory. JSON ledgers are replaced atomically after transitions. Reports are
not pruned automatically; remove old run directories deliberately when no longer
needed. The private checkout is removed on success, failure and handled signals.

Process exit status, explicit suite failures and descendant observations are
recorded separately. A descendant error remains diagnostic evidence when the
runner cannot establish the cause of the stage failure.

Each stage owns a POSIX process group. Cancellation, timeout, abnormal exit and
background descendants of a successful stage receive TERM followed by KILL;
cleanup completes before the next stage starts. Windows only guarantees direct
child termination. Detached descendants that create their own sessions escape
this mechanism. This is checkout isolation, not a sandbox for hostile commands.
SIGKILL, machine failure or an abrupt runtime crash can leave a private checkout
or a running/pending ledger. The candidate or certification report records the checkout location for
manual recovery. Reports survive ordinary cleanup, but are not power-loss/fsync
guarantees. Invocations have independent checkout/report directories and do not
share validation permissions or a mutable latest-success token.

The final index-tree and HEAD/branch checks occur after checkout cleanup. Git's
pre-commit interface does not provide an atomic lock spanning that check, hook
return, and commit finalization. Another process can still change the index or
HEAD in that final interval (including while the last report is written). Avoid
concurrent staging/committing while a commit finishes. Eliminating that race
requires a separately designed commit transaction; this hook does not claim it.
