

# v3.3.0 Release Notes — Identity, Authority, Typed Authoring, and Canonical State Ownership

## Overview

This release completes a major architectural convergence across HSON, LiveMap, LiveTree, Reflection, LiveHost, and the schema system.

The central model is now:

- **LiveMap owns canonical graph state.**
- **LiveTree owns rendered/runtime realization and interaction.**
- **Reflection carries authoritative canonical document state into LiveTree/DOM.**
- **LiveHost owns authorization, ordering, durability, synchronization, and recovery around a hosted LiveMap.**
- **Paths are the canonical mutation authority.**
- **QUIDs are sparse continuity markers rather than general-purpose identifiers.**
- **Schemas are immutable state-space contracts rather than replaceable validators.**
- **Typed paths, writes, attrs, and flags derive from the same schema evidence enforced at runtime.**

This release also completes a public schema-language redesign around:

```ts
schema.define(s => ...)
```

and closes several historical escape hatches and partial-generation APIs.

---

# Identity and QUID Coordination

## Reflected identity no longer mints private QUIDs

Linked LiveTree projections no longer create runtime-local identities for canonical nodes that do not already have identity.

Previously:

- Reflection could encounter an unquidded canonical node.
- LiveTree projection could privately assign a QUID.
- Projected runtime and canonical graph could temporarily disagree.

Now:

- canonical absence remains absence;
- supplied canonical QUIDs are preserved exactly;
- identity acquisition belongs to canonical authority;
- linked runtime registration follows canonical state.

Reflection no longer acts as a hidden identity authority.

---

## Authority-owned identity acquisition

Identity acquisition was redesigned around canonical ownership.

The system now distinguishes:

- canonical identity creation;
- runtime registration;
- projected correspondence.

Runtime objects no longer invent canonical identity.

Public identity-acquisition methods were removed before release:

```ts
map.ensureIdentity(...)
map.document.ensureIdentity(...)
```

Ordinary traversal remains passive and path-based.

---

## Sparse identity handles

Sparse identity handles support retained subject continuity without turning identity into ordinary traversal state.

They can:

- follow path movement;
- survive rename and array reindexing;
- track projected objects and arrays as well as document subjects;
- invalidate on replacement or retirement;
- preserve canonical identity metadata independently of handle disposal.

Primitives, scalar carriers, and structural-only wrappers do not acquire identity merely because they are traversed.

---

## QUID lifecycle hardening

Within a LiveMap owner epoch:

- issued QUIDs are tracked separately from currently active QUIDs;
- retired QUIDs cannot silently return;
- same-epoch ABA reuse is prevented.

Within a LiveTree runtime:

- terminal destruction permanently retires a QUID for that runtime lifetime;
- disposed handles do not reactivate retired lineages;
- equal QUID bytes cannot silently resolve to a new subject;
- a fresh runtime may independently admit equal bytes.

Collision, retired-reuse, and exhaustion conditions remain distinguishable.

---

## QUID representation hard break

Canonical QUIDs are now exactly **9 characters**.

Alphabet:

```text
0123456789abcdefghjkmnpqrstvwxyz
```

This provides a 45-bit namespace.

Older 16-character and other-width QUIDs are rejected rather than accepted through a compatibility path.

This is an intentional pre-epoch hard break.

---

# Path Authority and Document Traversal

## Paths remain canonical operation authority

The system now consistently distinguishes:

```text
path
    what is here now?

QUID
    where did this same subject move?
```

QUID-targeted internal requests lower back to current canonical paths before mutation.

Ordinary traversal, attrs, flags, rendering, and local mutation targeting do not mint identity.

---

## Logical document traversal

Document-mode LiveMap now exposes logical authoring coordinates rather than physical HSON carrier paths.

Examples:

```ts
map.at([0, 1])
map.at([0]).at([1])
map.proxy()[0][1].$_
```

Logical numeric traversal hides `_hson_str`, fragment carriers, and other physical representation details.

For element documents:

```ts
map.at([])
```

refers to the root element.

For fragment documents:

```ts
map.at([])
```

refers to the logical fragment/root container.

---

## Document location capabilities

Document locations now support current logical authoring operations, including:

- relative `.at(...)`;
- `snap()`;
- `watch()`;
- `.path()`;
- `.rev`;
- `replace`;
- `delete`;
- content insertion;
- content movement;
- attrs;
- flags;
- canonical `id()` discovery.

`id()` performs deterministic preorder discovery and returns a fixed-coordinate result. It does not introduce QUID identity.

Empty-fragment first insertion is treated semantically as content insertion rather than exposing root materialization details.

---

# Watch and Binding Convergence

## `location.watch(...)`

Projected and document locations now expose schema/value-aware watch semantics.

Watch behavior is:

- future-only on registration;
- equality-filtered for ordinary commits;
- explicitly notified once for successful restore/snapshot replacement, even when values compare equal;
- detached/value-only;
- independent of fallible feed/commit observer chains.

Watch listeners are isolated from one another.

A throwing watcher:

- does not prevent canonical state mutation;
- does not prevent other watchers;
- remains registered;
- observes an updated baseline on later changes.

---

## LiveTree bindings now use locations

LiveTree bindings were hard-replaced away from raw map/path authoring toward passive LiveMap locations.

Binding convergence now uses:

```text
initial snap
+
watch
```

rather than operation-feed semantics.

This fixes restore convergence and makes bindings consume the same location abstraction used by typed traversal.

Document locations are valid forward binding sources.

Structured document values are never implicitly serialized or coerced into primitive binding destinations.

---

# LiveHost Authority and Temporal Semantics

LiveHost authority now follows a stricter separation:

```text
interaction
→ client intent
→ LiveHost authorization/order
→ host LiveMap validation
→ canonical commit
→ durable record
→ broadcast
→ client LiveMap authoritative application
→ Reflection
→ LiveTree / DOM
```

LiveHost does not recreate graph semantics.

The hosted LiveMap remains responsible for determining the valid canonical transition.

---

## Commit chronology

LiveHost processing is strict FIFO.

The authority sequence is conceptually:

```text
enqueue
→ prepare
→ durable gate
→ isolated LiveMap acceptance
→ Host ingestion
→ history
→ publication
```

Durable append is the commit point.

Chronology now distinguishes:

- `rev` — canonical state chronology/recovery cursor;
- `seq` — action/live chronology.

Older duplicate recovery sequencing was removed.

---

# Transport and Canonicalization Hardening

Transport-totality work closed several edge cases across HSON, JSON, and HTML.

Notable guarantees include:

- negative zero remains distinguishable from positive zero;
- explicit `_hson_str` transport preserves adjacent and empty text segmentation;
- typed `_hson_val` values remain object-mode values and are not admitted under element mode;
- bare primitive HTML transport follows object-mode semantics;
- structural parsing precedes generic wrapping;
- multi-lap transport circuits preserve the original canonical baseline;
- strict canonical equality remains the circuit oracle.

Transport diagnostics distinguish:

- closure failure;
- projection failure;
- rejection;
- divergence.

# Unified Schema Architecture

## One public authoring boundary

Schema authoring now has one primary boundary:

```ts
schema.define(s => ONE_SCHEMA_EXPRESSION)
```

There is no projected/document callback split.

Removed forms include concepts such as:

```ts
schema.define(({ projected: s }) => ...)
schema.define(({ document: d }) => ...)
schema.document
```

There is one schema toolkit `s`.

The schema expression itself carries the domain capabilities required for composition.

---

## Defined schemas are first-class values

A defined schema is:

- immutable;
- reusable;
- owner-independent;
- evidence-preserving;
- compositional inside later schema definitions.

Example:

```ts
const Seat = schema.define(s =>
  s.object.exact({
    connected: s.boolean,
  })
);

const State = schema.define(s =>
  s.object.exact({
    left: Seat,
    right: Seat,
  })
);
```

Document schemas compose identically:

```ts
const Label = schema.define(s =>
  s.span(s.string)
);

const Button = schema.define(s =>
  s.button(Label)
);

const Toolbar = schema.define(s =>
  s.div(Button, Button)
);
```

This is intentionally analogous to TypeScript type aliases.

A new `schema.define(...)` call always creates a distinct schema contract even when it wraps or reproduces equivalent evidence.

Ordinary assignment preserves identity:

```ts
const Alias = Schema;
```

---

## Shared and domain-specific schema vocabulary

Some schema concepts genuinely span projected and document domains:

```ts
s.string
s.unknown
s.pick(...)
s.tuple(...)
```

Other concepts remain domain-specific where semantics differ.

Projected/value-oriented:

```ts
s.number
s.boolean
s.null
s.literal(...)
s.object(...)
s.object.exact(...)
s.array(...)
s.record(...)
s.tagged(...)
s.partial(...)
s.deepPartial(...)
s.recurse(...)
```

Document-oriented:

```ts
s.empty
s.repeat(...)
s.div(...)
s.button(...)
s.tag(...)
s.tag.foo(...)
s.attrs(...)
s.flag
```

Cross-domain misuse rejects statically and at runtime.

# Final Projected Schema Language

## Open and exact objects

Projected named-object schemas now use family-local exactness:

```ts
s.object({
  name: s.string,
})

s.object.exact({
  name: s.string,
})
```

Top-level:

```ts
s.exact(...)
```

has been removed.

The rule is now:

> `.exact` closes an otherwise-open named keyspace.

This same rule is used by attrs.

---

## Open-object typing now matches runtime

An open object:

```ts
s.object({
  name: s.string,
})
```

retains precise declared-property evidence while honestly representing valid runtime extras.

Conceptually:

```ts
{
  name: string;
}
& Readonly<Record<string, ProjectedValue | undefined>>
```

An exact object has no open index signature.

---

## Broad arrays

Zero-argument arrays are now explicitly typed and certified:

```ts
s.array()
```

means an arbitrary-length array of recursively legal projected values.

It is the broad equivalent of:

```ts
s.array(s.unknown)
```

within projected-array semantics.

It still rejects noncanonical/projected-invalid values such as:

- `undefined`;
- sparse holes;
- `NaN`;
- infinities;
- bigint;
- functions;
- symbols;
- boxed primitives;
- exotic or cyclic objects;
- document-only values.

Constrained arrays remain:

```ts
s.array(s.string)
```

---

## Tuple semantics

`tuple` remains a fixed ordered product.

Projected:

```ts
s.tuple(
  s.string,
  s.number,
)
```

describes a fixed positional tuple.

Document:

```ts
s.tuple(
  Header,
  Main,
  Footer,
)
```

describes a fixed sibling layout.

```ts
s.tuple()
```

remains a legitimate zero-position tuple/layout.

Tuple is not a generic exactness operator.

---

## Explicit document emptiness

Document exact-empty content now has a semantic spelling:

```ts
s.empty
```

Examples:

```ts
s.div(s.empty)
s.tag.foo(s.empty)
```

It lowers to the existing zero-length layout evidence; no separate empty IR was introduced.

`tuple()` remains valid but is no longer required as the preferred way to express document emptiness.

---

## Counted repetition

Document repetition now supports:

```ts
s.repeat(Item)
```

for zero-or-more siblings, and:

```ts
s.repeat(3, Item)
```

for exactly three siblings.

Counts must be primitive nonnegative safe integers.

Literal counts preserve fixed-coordinate evidence where TypeScript can represent it efficiently.

Dynamic numbers capture the exact runtime cardinality while using conservative static absence evidence.

Runtime representation remains allocation-constant rather than expanding into count-sized tuples.

---

# Schema Constraints and Recursion

## Fluent constraints

Constraint syntax is now schema-value-oriented:

```ts
s.number.constrain(
  n => Number.isInteger(n) && n >= -1
)
```

Optional labels are supported:

```ts
s.string.constrain(
  "lowercase slug",
  value => /^[a-z0-9-]+$/.test(value)
)
```

The old top-level form:

```ts
s.constrain(Base, ...)
```

has been removed.

Constraints:

- validate the base schema first;
- narrow the admitted runtime set;
- never transform, coerce, or normalize the value;
- preserve the base schema's structural/type evidence.

Defined schemas can also be constrained where their category permits it.

---

## `recurse` replaces `lazy`

Recursive and forward schema references now use:

```ts
const CircularSchema = schema.define(s =>
  s.recurse(() => CircularSchema)
);
```

The former `lazy` spelling was removed.

The public name now describes the feature's purpose rather than its evaluation mechanism.

Self-recursion, mutual recursion, memoization, and defined-schema composition remain supported.

---

## Removed descriptive-only `readonly`

The old schema `.readonly` modifier was removed.

It previously described metadata but did not prevent LiveMap mutation, creating a stronger static implication than runtime authority actually enforced.

No false readonly contract remains.

---

# Typed Document Paths and Writes

Schema evidence now drives document traversal across:

- direct `map.at(...)`;
- relative `.at(...)`;
- numeric proxy traversal;
- `snap`;
- `watch`;
- replacement inputs;
- insertion inputs;
- LiveTree bindings.

Examples:

```ts
map.at([0, 1])
map.at([0]).at([1])
map.proxy()[0][1].$_
```

resolve equivalent schema evidence.

Known text positions resolve as `string`.

Known element positions resolve as `HsonNode`.

Dynamic/repeated/union positions include truthful absence where necessary.

Exact impossible direct paths reject statically.

---

## Schema-aware mutations

Document replacement inputs are narrowed from endpoint evidence.

Examples:

- text location → `string`;
- element location → `HsonNode`;
- mixed branch → appropriate union.

Read-side `undefined` does not automatically become a writable value.

Insert inputs are likewise derived from content/layout evidence.

Destructive operations whose validity depends on current state remain callable where appropriate and are finally governed by runtime candidate validation.

---

# Permanent Schema Ownership

A successfully attached schema is now a permanent contract of its LiveMap owner.

Given:

```ts
map.schema.use(A)
```

the rules are:

```text
first use(A)
    validate current state
    attach exact object A

use(A) again
    idempotent no-op

use(B), B !== A
    reject
```

This includes independently defined but structurally equivalent schemas.

Schema identity is ordinary object identity.

A single schema value may govern multiple independent maps.

---

## Attachment is governance, not a state transition

Successful first attachment:

- does not increment revision;
- does not create a commit;
- does not enter history;
- does not fire watch;
- does not publish feed events;
- does not change QUIDs;
- does not clone or replace canonical graph state.

Failed first attachment is inert.

Rejected schema replacement is also inert.

---

# Canonical State Encapsulation

## `debug.node` removed

Public `debug.node` and the corresponding mutable-node-handle family have been removed.

LiveMap now owns canonical state for its entire lifetime.

Public callers may:

- observe detached values;
- retain path/location handles;
- request mediated mutations.

They may not acquire mutable canonical graph ownership.

Removed public node-handle/debug types include the former mutable LiveMap node APIs and related attr/content manipulation handles.

---

## No public canonical-state aliases remain

Audits and tests cover:

- constructor inputs;
- snapshots;
- captures;
- locations;
- proxies;
- watch/feed payloads;
- commit/history results;
- restore/replay inputs;
- schema inspection.

Public structured observations are detached, frozen, immutable, or mutation-governed.

A private internal reader remains for low-level implementation/testing and LiveInspector, but is not exported through supported package entrypoints.

# Typed Document Attributes

Document schemas can now govern element attrs directly.

Example:

```ts
const CommonAttrs = schema.define(s =>
  s.attrs({
    id: s.string,
    title: s.string.optional,
  })
);

const Card = schema.define(s =>
  s.div(
    CommonAttrs,
    Child
  )
);
```

Attrs schemas are first-class defined schemas but are not root-attachable.

They must appear at most once and as the first tag operand.

---

## Open and exact attrs

```ts
s.attrs({
  id: s.string,
})
```

is open:

- declared attrs are constrained;
- additional canonical attrs may exist.

```ts
s.attrs.exact({
  id: s.string,
})
```

is exact:

- undeclared attrs reject.

```ts
s.attrs.exact({})
```

means no attrs.

Omitting attrs evidence entirely preserves broad canonical attrs.

---

## Attribute presence and values

Existing schema vocabulary is reused where semantically truthful:

```ts
s.string
s.number
s.boolean
s.null
s.literal(...)
Schema.constrain(...)
s.recurse(...)
s.unknown
```

Optionality maps directly to attr absence:

```ts
title: s.string.optional
```

Explicit `undefined` remains invalid.

Nullable means present-null is legal:

```ts
title: s.string.nullable.optional
```

---

## Typed attr reads and writes

Schema-bound document locations now specialize existing attrs APIs.

For:

```ts
s.attrs.exact({
  id: s.string,
  title: s.string.optional,
  role: s.literal("button", "switch"),
})
```

location typing can express:

```ts
attrs.get("id")
// string

attrs.get("title")
// string | undefined

attrs.get("role")
// "button" | "switch"
```

Exact undeclared literal keys reject.

Open attrs preserve broad extra-key typing.

`keys()` can return a declared-key union under all-exact evidence.

Mutation APIs remain the existing surface:

```ts
attrs.set(...)
attrs.setMany(...)
attrs.drop(...)
attrs.dropMany(...)
attrs.replace(...)
attrs.clear()
```

`setMany` remains an atomic patch/overlay.

`replace` supplies the complete replacement bag and therefore receives stronger whole-shape typing.

Destructive operations whose resulting validity depends on current state remain runtime-authoritative.

---

# First-Class Flags

Flags are now a first-class semantic concept without reintroducing a separate canonical storage property.

Canonical flag form is:

```ts
attrs[name] === name
```

For example:

```ts
{
  selected: "selected"
}
```

No hidden flag-intent metadata exists.

---

## Flag schemas

Attr schemas can express contextual flags:

```ts
s.attrs({
  disabled: s.flag,
  selected: s.flag.optional,
})
```

`s.flag` means:

> the containing attr must be present in same-name canonical flag form.

It is distinct from:

```ts
s.boolean
s.string
s.literal("true", "false")
```

Flags are not booleans.

---

## LiveMap flag API

Document locations and explicit-target document APIs now expose:

```ts
location.flags.has(name)
location.flags.set(...names)
location.flags.clear(...names)

map.document.flags.has(target, name)
map.document.flags.set(target, ...names)
map.document.flags.clear(target, ...names)
```

`flags.set` atomically establishes same-name flag state.

`flags.clear` removes only attrs currently in exact flag form.

Routine flag operations do not mint QUIDs.

---

# LiveTree / LiveMap Attr Convergence

LiveTree and LiveMap now expose the same complete canonical attr-bag semantics.

The former LiveTree private flag `WeakMap` partition has been removed.

Previously, LiveTree could treat a same-name value as either:

- an “ordinary attr”; or
- a separately classified flag.

That distinction could not survive cloning, capture, replay, Reflection, or reconstruction because it was not represented canonically.

Now:

```ts
tree.attrs.set("selected", "selected")
```

and:

```ts
tree.flags.set("selected")
```

produce the same canonical state.

Therefore:

```ts
tree.attrs.get("selected")
```

observes the same-name value, and:

```ts
tree.flags.has("selected")
```

returns true.

---

## Complete attr-bag operations

LiveTree attrs now operate on the complete canonical bag.

Consequently:

```ts
attrs.drop(name)
```

removes the attr regardless of whether it happens to be in flag form.

```ts
attrs.clear()
```

clears the complete attr bag.

```ts
attrs.replace(values)
```

replaces the complete bag.

`attrs.setMany(values)` remains an atomic semantic patch/overlay.

---

## Shared semantic planners

Pure canonical attr/flag planners now provide shared semantics for:

- set;
- setMany;
- drop;
- dropMany;
- replace;
- clear;
- flag recognition;
- atomic flag set;
- atomic flag clear.

LiveTree and LiveMap still retain separate:

- target resolution;
- mutation authority;
- schema validation;
- commit execution;
- DOM projection;
- return contracts.

LiveMap never implements canonical mutation by invoking stateful LiveTree/DOM setters.

---

## Bound LiveTree flags now delegate canonically

For a LiveTree node backed by a LiveMap document:

```text
LiveTree flag operation
→ backing LiveMap path
→ canonical candidate
→ schema validation
→ commit
→ Reflection
→ LiveTree / DOM
```

This eliminates projection-only flag divergence.

No QUID is required merely because a bound flag is changed.

---

# Style Scope

Inline style remains canonical structured attr state under the `"style"` key.

H1 deliberately does **not** introduce a LiveMap style convenience namespace.

Canonical style may still be read or replaced through attrs:

```ts
location.attrs.get("style")
location.attrs.set("style", styleMap)
location.attrs.drop("style")
```

Schema H1 can truthfully keep style broad:

```ts
s.attrs({
  style: s.unknown.optional,
})
```

CSS-property-level schema typing, canonical style patch helpers, and explicit presentation-only style authority remain deferred.

---

# Schema Issue Improvements

Schema issues can now associate failures with attrs without inventing fake document path coordinates.

Added:

```ts
LiveMapSchemaIssue.attributeName?: string
```

An attr error can therefore retain the real logical document path:

```ts
{
  code: "INVALID_CONSTRAINT",
  path: [0, 2],
  attributeName: "tabindex"
}
```

Existing issue codes are reused for attr/schema failures.

# Breaking Behavior Changes

This release intentionally makes several previously permitted behaviors fail.

## QUID width

Older 16-character and noncanonical-width QUIDs reject.

Canonical QUIDs are exactly 9 characters.

---

## Terminal QUID reuse

A QUID retired in one LiveTree runtime cannot be silently reused for a different lineage in that same runtime lifetime.

---

## Reflected private identity

Linked LiveTree projections no longer acquire private runtime-local identity when canonical state has none.

---

## Schema replacement

A LiveMap schema can no longer be replaced after successful attachment.

Equivalent-but-distinct schema objects also reject.

---

## Raw canonical-node access

`debug.node` and mutable public node handles are gone.

---

## LiveTree attr/flag partition

LiveTree attrs no longer hide or preserve an ephemeral separately classified flag subset.

Attrs operate on the complete canonical bag.

---

## Schema syntax hard replacements

Old schema spellings and aliases described above reject rather than route through compatibility behavior.

# Architectural Result

The resulting system can now be summarized as:

```text
schema.define(s => ...)
        ↓
immutable state-space evidence
        ↓
LiveMap owner
        ↓
typed path/location/proxy
        ↓
typed reads / writes / attrs / flags
        ↓
candidate canonical graph
        ↓
schema validation
        ↓
commit
        ↓
LiveHost chronology when hosted
        ↓
Reflection
        ↓
LiveTree / DOM
```

The major invariants are now:

> **LiveMap owns canonical state for its lifetime.**

> **A successfully attached schema permanently defines that owner's legal future state-space.**

> **Paths are operation authority; QUIDs are sparse continuity.**

> **LiveTree and LiveMap reuse semantic operations where they genuinely agree, but do not share mutation authority.**

> **Public callers may observe or request changes to canonical state, but do not acquire mutable ownership of the canonical graph.**
