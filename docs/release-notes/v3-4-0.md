# Changes:

# renaming & rebranding

## `HSON` -> `Hson` 
Changed `HSON` name to `Hson` across docs, names, and types. General day-to-day usage is `Hson`, with `HSON` reserved to mean the acronym for "Hypertext Structured Object Notation" in narrow usage cases.

## `projected` -> `data`
Changed unsemantic `projected` references to JSON data in docs and filenames. JSON-source graphs are now idiomatically `data`, mirroring HTML-context's corresponding `document`.

## removed: `fragment`
Finally excised a third graph context, `fragment`, that still haunted the codebase. Suspicions that the term didn't provide helpful context were confirmed when and audit found its described graphs structurally identical to documents and simply lacked a single shared root node. _hson_root wrapping is the idiomatic solution to this problem and the reason for the node's existence; multiple HTML graph inputs are now accepted as documents, wrapped in _hson_root as carrier, and unwrapped on output. 

# LiveHost/Locus

## Renamed the one-LiveMap authority subsystem from LiveHost to Locus, hard-cut the public API accordingly.
• Added `hson-live/locus` and `hson-live/locus/node`; renamed the one-map surface to `Locus*`, including `create_locus`, `create_locus_client`, `create_persistent_locus`, `LocusClientId`, `LocusLogicalMapId`, `LocusIncarnationId`, and `LocusSelector`. Removed the old one-map `hson-live/livehost` surface, compatibility aliases, forwarding shims, `hello.hostId`, `?livehost=`, `authoritySelector`, versioned bootstrap forms, and one-map `LIVEHOST_*` / `"livehost"` error and trace branding.

## Clarified LiveMap/Locus representations, recovery, persistence, and bootstrap contracts.
• Removed legacy/exact/versioned capture families, `formatVersion`/`viewStateVersions` generation machinery, legacy QUID-only canonical commit compatibility, and redundant protocol decoders. The current bootstrap is now the unversioned `LocusBootstrap` with format `"hson-locus-bootstrap"`, media type `application/vnd.hson-live.locus-bootstrap+hson`, and `locusSelector`; canonical history and persistence remain path-authoritative while raw-QUID request targeting continues to lower to paths.

## Established LiveHost application-runtime boundary above Locus
• Added `hson-live/livehost` with platform-neutral `LiveHost`, `LiveHostApplication`, Web `Request`/`Response` routes, `LiveHostConnection` (`string | Uint8Array`), `LiveHostPrincipal`, lifecycle/readiness contracts, and `create_livehost_locus_registry`. The existing `hson-live/livehost/node` runtime was adapted to this model, making zero-Locus applications first-class while keeping application topology and Locus selection application-owned. The bounded registry gained `automaticSweep?: boolean` so applications can explicitly own idle scheduling when required.

## Worker is now a compatibility runtime
The Worker architecture remains supported, but its role is clearer as a compatibility intermediary.

## Hson hashing

Implemented SHA-256 support as an output constructor option. A hash describes the emitted serialization after canonicalization. Any format (JSON, Hson, or HTML) can be output as a SHA-256 hash for portable diagnostics.

# Identity and Continuity

## QUID as continuity metadata

The identity model solidified QUIDs as ephemeral identity markers rather than permanent reliable properties. 
Transportable or serialized node references should use paths for consistent access.

• QUID - transient and ephemeral runtime-scoped identity
• path - durable location-based mutation authority

QUID policy reinforces the goal of near-invisibility to users. Serialization of QUIDs for representational continuity, inclusion in document markup for runtime queries, and self-authoring of QUIDs remains unsupported.

# LiveMap — major changes completed

## Multi-Maps

• Replaced the one-map/one-domain assumption with **multi-library LiveMap**
• One LiveMap can now own multiple independently Schema-governed data and document libraries under one revision/history/transition authority.
• Added multi-map public construction through `hsonLiveMap.fromLibraries(...)`.
• Added typed library selection through `map.lib(name)`
• Enforced one global commit stream across libraries: one `prevRev`, one `rev`, and one ordered list of library-qualified operations.
• Made aggregate multi-library transitions atomic across affected libraries.
• Added defaults to multi-LiveMap: `map.at([path])` accesses the 'default data' map; map.document.at accesses the 'default document' map. 
• Added named document-library support with writable document facades, root/at/proxy/capture access, commit feeds, and Schema access.
• Integrated named document libraries with **Reflect**, including continuity across unrelated library revisions, recovery, snapshot replacement, and restart.
• Removed `FragmentLiveMap`; unified document authority around `DocumentLiveMap`
• Wired hosted multi-library support through the existing Locus/LiveHost path, including client mirrors, subscriptions, replay, recovery, persistence, restart, and QUID/ABA continuity.
• Adjusted hosted snapshot/commit representations to preserve library registry, roots, Schema identity, revisions, and issued QUID history.
• Preserved solo LiveMap compatibility and devised map.migrate pattern for promotion to multi-map
• Multiple, independent LiveMaps (versus a single multi-map) is technically possible but not recommended for most use cases

# HsonSchema

A wholesale reconsideration of the schema component resulted in stronger schema-to-type guarantees and an unlock in HsonExtension schema-checking capabilities during authoring. 

## replaced executable Schema builer 
Schema is now expressed as valid Hson and compiles into a verified immutable CanonicalSchemaGraph. Arbitrary callback constraints and executable recursion are no longer part of Schema authority.

## established HsonSchema as the single Schema system 
Retired LiveMapSchema, old builder/inference APIs, .schema.validate, callback constraints, and the legacy constructor-authoring surface.

## added the HsonSchema meta-schema/compiler pipeline

Authored Schema is parsed as Hson, checked against the Schema language, lowered deterministically, verified canonically, and rejected before runtime use if malformed or semantically invalid.

## implemented automatic Schema → TypeScript generation

Each authored Schema can produce real workspace symbols such as <Name>Type and <Name>Hson, with generated evidence kept private.

## made static Hson authoring Schema-bound by type association

A declaration typed as <Name>Hson is automatically checked against the corresponding Schema; no explicit validation call is required for static authored Hson.

## implemented core data Schema semantics. 

Includes primitives, exact values, required/optional members, closed data structures, arrays, tuples, restricted unions, and recursive composition.

## added Hson.certify for dynamic admission 

Runtime Hson can be checked against a HsonSchema and returned unchanged with the exact Schema-bound Hson proof.

## implemented proof-bearing generated types

Schema constraints that TypeScript cannot represent retain nominal proof rather than collapsing to broad primitive types.

Added contraints for `int`, `min`, `max`, `over`, `under`, `len`, `minlen`, `maxlen`, `prefix`, `suffix`, `contains`, and `unique`.


## separated mutation candidates from governed proof-bearing state. 

LiveMap accepts ordinary structurally valid candidate values, validates them against the Schema before commit, and exposes proof-bearing reads only after successful acceptance.

## implemented document Schema semantics. 

Unified document handling under the same internal model, including exact tags, attrs, ordered content, sequences, repeat/count, recursive document structures, and multi-top-level documents without a separate Fragment concept.

## added declarative composition and recursion with defs / ref. 

Supports reusable definitions, forward/backward references, self recursion, mutual recursion, canonical productivity checking, and finite recursive TypeScript generation.


## integrated Schema into new `multi-LiveMap` library governance
## enabled downstream Schema tooling in the Hson VS Code extension

## repaired fail-closed freshness and generated-evidence checks.

Schema edits, renames, ref changes, topology changes, and stale generated artifacts invalidate prior evidence rather than being silently accepted.

## standardized Schema across local, hosted, and multi-library LiveMap. 

Per-library Schema authority survives aggregate commits, client replay, recovery, persistence, restart, and named document reflection.

## preserved one shared authority across editor, build, and runtime. 

The VS Code extension, generator, analyzer, LiveMap, and runtime certification all consume the same HsonSchema compiler and anonical graph semantics rather than maintaining parallel duplicate rule sets.

# Audits & Cleanups

### LiveTree authority was tightened.
  - Bound form mutations now go through LiveMap authority.
  - Canvas canonical sizing now passes authority before DOM realization.
  - Failed reflection no longer exposes incoming descendants as accidental standalone LiveTrees.
### LiveTree lifecycle and ownership were hardened.
  - Failed private creation unwinds owned branches.
  - text.overwrite now disposes displaced descendants.
  - Failed bridge/listener setup unwinds subscriptions.
  - Failed initial Reflect construction disposes its private tree.
### LiveTree DOM/runtime boundaries improved.
  - Several accidental ambient-DOM-realm dependencies were removed.
  - Explicit-Document and foreign-realm operation is materially stronger.
### Inline style correctness was repaired.
  - Editing one style declaration no longer drops unrelated structured style values.
  - Initial style projection now uses the same canonical serialization as later updates.
### Reflect gained stronger failure/authority behavior.
  - Correspondence is established early enough that failed realization cannot create authority bypasses.
  - Failure cleanup better preserves ownership invariants without rolling back canonical LiveMap commits.
### Hson documentation was substantially repaired and consolidated.
  - Current canonical references now exist for Transform, LiveTree, LiveMap, Reflect, and Locus.
  - LiveMap capture/restore/replay behavior and Transform binary/hash behavior are now documented against current code.
