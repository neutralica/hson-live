## 2. Capture/instrumentation architecture

The existing explicit provider instrumenter wraps only binding-discovered official
Hson tags in the diagnostic copy. It verifies the real Hson identity, calls the
unchanged tag, and records evidence separately. No application files, loaders,
public values, or Schema definitions are rewritten. The editor only discovers,
requests, maps and presents evidence; the trusted child executes expressions.

The only production factoring is one private shared primitive encoder function.
Capture reuses it after the real tag to record generated scalar source. This is
pure primitive re-encoding, not a second serializer, expression evaluation or
Hson parse. No trace is requested or generated by ordinary production Hson.

## 3. Exactly-once evaluation

Confirmed: original expressions execute once, in normal tagged-template order.
The real tag receives the original TemplateStringsArray and original primitive
arguments. Expression exceptions prevent tag invocation; admission exceptions
are captured and the original thrown object is rethrown. Unsupported objects
are not coerced, cloned, inspected or retained. Successful returns remain
primitive HsonCanonical strings.

## 4. Exact private trace contract

`InterpolationCapture` contains:

- `evaluationId`;
- `site`: module URL, static occurrence ID, whole-host SHA-256 revision,
  template range, expression ranges, literal raw strings/ranges/boundary tables;
- `source`: completed generated Hson, or its partial prefix if encoding failed;
- alternating `segments`: kind, index, generated start/end, substitution kind;
- actual `canonical` return on success;
- `failure`: original message, structured Transform details, offending
  substitution index when primitive admission failed;
- admission/trace timings.

Primitive values are represented exactly by their authoritative encoded source,
including negative zero. Generation and request IDs use the existing protocol
envelope. D2/D3 associations add application/relationship identity, Schema handle,
document/template/association versions and evaluation ID. Capture storage resets
on load; caps are 256 evaluations, 1,000,000 generated UTF-16 units per evaluation
and 4,000,000 total. Overflow disables evidence rather than evicting to a latest
value. Nothing is exported from a public package entrypoint.

## 5. Generated-source mapping contract

Generated intervals explicitly distinguish literal source from encoded values.
Ranges wholly within one origin map through that origin. Cross-origin ranges
enclose the contributing host origins and are non-exact. Unresolved evidence
uses the complete template. The generated C1/C2 precision is retained separately
from host-origin precision.

## 6. Literal-segment behavior

Literal UTF-16 boundaries map to physical host UTF-16 boundaries. Mapping never
assumes runtime raw-string offsets equal host offsets. Literal ranges remain
character-exact where possible; EOF maps immediately before the host backtick,
including an empty trailing literal.

## 7. Substitution policy

Primary range is the TypeScript AST expression body, excluding `${` and `}`
and leading/trailing trivia. Discovery admits only syntactically reliable
expression ranges; damaged templates are omitted. Every generated subrange
inside a substitution maps to that entire expression, never fictional generated
quote characters. This is reported as `substitution-expression`, not `exact`.

## 8. CRLF, Unicode and escapes

Physical CRLF and lone CR normalize to LF as tagged templates require; boundary
tables retain physical host widths. Astral characters count as two UTF-16 units.
Parser points use the existing Unicode-safe point mapper. Raw backslashes,
escaped backticks and escaped `${` spellings remain raw and parser-owned.

## 9. Admission-error mapping

Unsupported values and nonfinite numbers map to the offending expression.
Completed-grammar failures map the authoritative parser point through the
generated-source map, to literal or substitution origin as appropriate.
Source-less failures remain unresolved. No map construction or validation call
is required. The real exception still stops provider application execution;
the loader can retain preceding evidence alongside explicit `loadFailure`.
VS Code labels admission diagnostics `Hson`, separately from `Hson Schema`.

## 10. D2 standalone validation

Existing bounded source association selects one exact, current evaluation and
the actual registered Schema. The runtime reparses the completed source with
provenance, validates through existing graph authority, applies C1/C2, and maps
to the host. A test explicitly stops application execution before its
`Hson.validate` statement and still obtains the source-bound diagnostic.
Independent Schema relationships validate independently.

## 11. D3 map/schema integration

Actual map construction and attachment use existing lifecycle authority.
Application evidence now carries the selected evaluation ID. The runtime requires
that exact evaluation, not equal canonical text. Rejected initial attachment,
multiple Schemas/maps, revision checks, mutation suppression and mutate/revert
suppression are preserved. Ambiguous evaluation cannot acquire new lifecycle
authority; the actual application operation still executes.

## 12. Repeated evaluation/ambiguity

Every executed tag gets a new evaluation ID. No last-value, timestamp or
canonical-equality selection occurs. Multiple evaluations at a source relationship
are ambiguous even if their values are equal. A fresh capture request and
association/validation checks detect repetition after load and after association;
evidence is checked again after Schema execution.

## 13. Freshness/staleness

Evidence is tied to source URI, whole-document SHA-256, occurrence, evaluation,
association/application, Schema, generation, request and editor version. Any
relevant editor change immediately removes published diagnostics before debounce.
Unsaved literal/expression edits, including edit/revert, wait for fresh provider
evaluation. They neither replay old values nor repeatedly consume restart budget.
The existing save/reload/configuration lifecycle supplies a fresh generation.
No byte/value equality overrides the revision checks.

## 14. Trust-off behavior

Both Workspace Trust and explicit enablement remain mandatory. Closed gates
prevent provider startup and expression execution. Secure discovery/highlighting
and TypeScript expression diagnostics remain available; interpolated Hson gets
no speculative whole-template validity claim. Real Restricted Mode tests verify
that the provider-execution marker does not change.

## 15. Host precision

Private host origins are `literal-exact`, `substitution-expression`, `anchor`,
`composite`, and `unresolved`. Missing structure retains anchor presentation;
cross-origin diagnostics explicitly disclaim character precision; unresolved
diagnostics remain template-level. Generated `exact` never turns a JavaScript
expression into a purportedly literal Hson token.

## 16. Representative wording

\"draft\" | \"published\" here.”

Wording uses structured kind/issue/constraint evidence, not English-message
parsing. No arbitrary-code fix is invented.
