Installed read inventory and migrated routes

* aggregate_snap now resolves the installed HsonNode graph and materializes only
  the selected node. Named Library snap, path handles, internal path authorities,
  update callbacks, and watch/feed snapshot values use this route.
* aggregate.projectedValue now produces a temporary immutable projection of the
  selected graph subtree, with an optional path; it no longer returns retained
  library.projectedValue. Ordinary callers supply a selected path.
* Named and legacy handle hson reads use selected graph projection followed by
  hson_data_text_from_value and the existing exact serializer. No JavaScript
  object recapture occurs. Missing paths remain undefined; must reads fail.
* The existing private propagation capability now supplies snap, kind, keys and
  length as well as selected ordered projection. Shape refinements, object
  presence/key/getKey, array length/index/first/last, and collection guards use
  these graph-local operations. Keys preserve physical graph order.
* Array slices/take/drop/last variants materialize only selected items; toArray
  and map materialize the selected array directly. Object toObject/getKey also
  materialize directly. Sorting, equality scans, object values/entries and
  pick/omit can temporarily project the complete selected container. pick/omit
  preserve their read-before-caller-key-list-access snapshot timing, including
  reentrant getters. These are temporary values, not retained caches.
* Installed Part selection and composition project only the selected admitted
  member; Part write reads only its document string. Membership checks are
  graph-local. Pending transaction Part values remain ordered candidates.
* Interaction activation, current-subject lookup and installed descriptor storage
  select the descriptors graph member. Installed subject validation also reads
  this member from the graph. Interaction drafts remain ordered candidates.

Canonical machinery and direct materialization

The existing LiveMap resolve_value_node/project_live_path machinery qualifies
selected paths. The canonical projected-value graph decoder now shares one
traversal between ordered output and direct JavaScript output. It reuses
admit_hson_number, canonical scalar checks, transparent-wrapper rules, property
name checks, array occurrence/index checks, duplicate rejection, and safe own
property creation. Direct output writes its result containers as it traverses;
it does not allocate a complete intermediate ordered value or decoded-entry
representation. Static reader strategies contain functions only, not Data.

Direct reads preserve signed zero, finite extremes/subnormals, null, booleans,
strings (including lone surrogates), empty containers, nested structure, and
safe own __proto__/constructor members. Snapshots are detached and writable at
runtime as before. Integer-like keys follow JavaScript enumeration rules in
ordinary objects; exact order is proved with graph keys, carriers and Hson.

Unsupported tags, malformed scalar payloads, reserved properties, duplicate
members, sparse graph content, malformed relationships and invalid array index
metadata fail. No failed canonical projection is replaced with a successful
fallback. Duplicate failure is deferred until all children are decoded, matching
canonical ordered projection's failure precedence. Constant-work shape queries
rely on the already-admitted installed graph; they do not recursively re-admit
entire containers.

Differential evidence: 200 deterministic nested structures per runtime, explicit
scalar/container and transparent-wrapper cases, root and nested selections,
22 malformed graph cases, exact Hson comparisons, and thrown getters in unrelated
subtrees. Each direct materialization is checked against
materialize_projected_value(project_live_path(...)) and independently authored
ordered values. Graph and exact serialization witness numeric member order.

Narrow correction after independent review

Public snap_live_path compatibility:
  Data context is chosen structurally from the root value relationship. Root
  Data reads use the shared strict canonical decoder. Selected Data reads check
  root/member/item arity, names and index relationships using shared canonical
  relationship machinery. No decoding exception selects permissive behavior.
  Generic Document observations retain the historical node_to_json_value path;
  its canonical Data branch now materializes directly. The valid <main/>
  reproduction returns {}, matching R1, instead of throwing. Generic Transform
  and Document admission are unchanged.

Array ranges:
  The private arrayRange capability selects/qualifies one graph array, captures
  its content reference locally, computes bounds against that length, and
  materializes only returned occurrences through the canonical item decoder at
  their original physical indexes. The selection is never retained. Candidate
  adaptation remains ordered and immutable. slice/take/drop/takeLast/dropLast
  share this route. Refined handles retain one additional fixed shape guard;
  selection/guard counts are independent of returned item count (including 0).
  No JavaScript materialization/recapture or persistent cache is introduced.
