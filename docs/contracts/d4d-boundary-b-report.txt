3. Removed storage and obsolete pathways

LiveMapLibraryState.projectedValue and LiveMapSystemState.projectedValue are
removed. No hidden compatibility field or complete retained projection cache
replaces them. installed_projected_value and the optional-path complete-value
projectedValue capability are removed; the remaining projectData capability
requires an explicit selected path and projects the graph on demand.

The old value-bearing AggregateDataCandidate and AggregateSystemCandidate,
projected_candidate_graph reconstruction, must_hson_schema_projected_candidate
reconstruction, plan_write_ops_with_identity wrapper, and ordered_candidate_reads
adapter are removed. The existing plan_write_ops is refactored in place, not
joined by another mutation engine. Its result carries immutable operation
evidence, not a second complete candidate value. Full graph/value installation
assignments and field-presence guards for ordered storage are gone.

4. Candidate ownership and editing

Each ordinary touched Data Library has two independent deep graph clones:
baseRoot is the detached stale witness; root is the private mutable candidate.
Neither aliases the installed graph or each other. Scalar metadata records are
independently copied; structured style attributes still receive deep copies.
One evolving candidate serves
all ordered operations on that Library in a transaction. Existing endpoint
editors perform root, nested and indexed writes. Constructive set applies each
submitted member in its existing order, as shallow endpoint assignments.

Rename, move and splice project only their selected container, use the existing
ordered mutation functions, then write the result into the private graph. A
physical container replacement remains a semantic rename, move or splice in
transport evidence and QUID reconciliation. Collections use the same candidate
through the existing array/object helpers. No per-operation whole-Library
projection is used to implement a narrow write.

Installed Data retains its stable root object and receives copied candidate
content only during accepted installation. Candidate graphs and stale witnesses
remain independent during preparation/reservation/rejection. Canonical graph
comparison, revision/generation checks and identity fences all remain; pointer
identity or value equality does not replace those checks.

5. Operation and root-shape evidence

Focused Node/Worker cases cover ordinary equal set versus explicit equal replace,
identity retirement and issued-ledger ABA rejection, moves between equal objects,
rename source/destination identity, equal-content splice removal, numeric-looking
member order, shallow constructive assignment, signed zero and finite extremes,
missing paths, forbidden root deletion and complete-Library depth rejection.
Existing root, wrapper, rename, move, splice and ordering suites remain active.

Root shape is applied from normalized authored intent. An equal explicit root
replace followed by a changed operation produces the intended wrapped root even
when the equal operation itself has no semantic change. Ordinary equal root set
keeps its established normalization. Internal root container edits preserve a
direct Data root. Root-mode restrictions and multi-Library epoch reset restrictions
remain intact.

Accepted equal replacement/splice evidence is replayed in a fresh runtime even
when the receiver has none of the source runtime's QUIDs. Replacement must target
an identity-eligible semantic container; splice must remove at least one eligible
child. The replay path checks exact prev/next values and exactly one accepted
semantic operation. Empty splices and equal primitive effects reject. Section 14
records the narrowing of the originally overbroad replay exemption.

The maintained byte-evidence comparison bundles committed HEAD and current source
in temporary directories. Fourteen representative commits compare byte-exactly
after substituting only nondeterministic authority IDs. Final exact Hson and
revision also match. Equal identified splice retirement is separately asserted;
it is intentionally a semantic operation even when replacement content is equal.

6. Parts, interactions, installation and restoration

Parts retain the established preplanning and Parts-before-Document composition
order. Baseline immutability checks use installed graph keys/shapes; exact catalog
preservation/addition validation uses bounded temporary catalog projections.
Composition reads pending members from the same evolving private candidate.
Part admission values are transient authored/validation input, not installed Data.
The receiver clears its initial definitions binding after setup so its long-lived
closures cannot accidentally retain complete Part admission values.

Interaction state now owns only a graph. Its baseline and candidate are detached
independent clones, and descriptor rewrites, collection planning and client/shared
partitioning use temporary selected descriptor values. System candidate validation
rejects QUID claims and never issues system Data identities.

Initial and dynamic Library admission, prepared installation, semantic checkpoints,
local topology restoration, aggregate restoration, client projection restoration,
portable hosted replay and managed client projection preparation have all lost
their retained-value synchronization assignments. Existing topology, checkpoint,
Part, scoped identity and interaction replay suites exercise these branches.

7. Qualification, Schema, identity and authority

Every final candidate is qualified as a complete canonical Data graph and checked
against its genuine governing Schema. The existing D4b ordered Schema evaluator
receives a temporary final graph projection. No new evaluator or mutable Schema
contract is added. Canonical validation checks the total Library nesting depth,
reserved names, exact member order, finite numbers, wrappers and relationships.
Portable generated-QUID rejection and Schema diagnostic/certification identity
remain in the established admission/evaluation boundaries.

The single aggregate transition controller still governs mixed Data/Document/CSS
installation. Exact management grants, revisions, preparation generations, identity
generations, reserved durable decisions and current-state fences remain. Existing
QUID overlays/issued ledgers, retirement/ABA protection, scoped QUAD lifetimes,
same-runtime restoration provenance and fresh portable restoration are retained.
No authority is moved into Locus or Echo.

8. Prepared-token and scratch lifetimes

WeakMap authority records retain expensive checking/installation/publication
callbacks only while pending. Success, genuine no-op acceptance, discard, detected
staleness and failed installation release pending callbacks and planning-only
candidate/baseline maps. Core also removes preparedSystemRoots entries. Terminal
commit evidence remains available; accepted/discarded/stale terminal errors keep
their established behavior. A revoked reserved management grant preserves its
immediate management error; a later changed revision/generation produces the
established stale error. A competing reservation is a temporary fence, not a
reason to discard another still-valid preparation.

No global strong token registry is introduced. Locus clean/uncertain append
failures discard planning state while uncertain-outcome authority fencing remains.
Disposal during reservation defers ownership release until settlement. Session
projection, queued publication, replay reservations and retained history own
separate evidence and are not cleared with planner maps. Reentrant publication
keeps its original order. Staged writers clear commands after consumption plus
closure, or explicit authoring failure; close() then writes() still hands off the
captured commands. Tests retain that returned immutable command list for later
inspection rather than relying on a consumed scratch queue.
