# Local portable document subject handoff (Cut 8E)

This is a bounded internal connection between Cut 8D SSR and existing exact
adoption, local Mirror, and bound document CSS. No package export, public option,
identity issuer, authored attribute vocabulary, or additional CSS owner is added.

## Owned path

1. `cut_document_ssr_internal` produces HTML and portable sibling state from one
   graph/CSS/correspondence candidate. QUAD carriers and recognized CSS selectors
   address the same subjects. The incoming generated payload is preserved exactly.
2. `restore_portable_document_receiver_internal` uses the existing aggregate
   decoder/factory and Cut 8B restoration once. It returns the ordinary receiving
   map and that installation's `PortableQuadRestoration`, including final-only
   captures without source component Libraries. Restoration issues fresh sparse
   receiver QUIDs; only explicitly authored associations enter authored bindings.
3. `preparePortableDocumentHandoff` on the restoring aggregate validates provenance,
   Library identity/name, issuance, current overlay coordinates, ordinary subjects,
   and explicit dispositions. It uses Cut 8C to prepare incoming CSS translation.
   Private weak sets authenticate installation/candidate objects; they contain no
   subject lookup, identity issuance, or independent authored-name authority.
4. `continue_portable_document_internal(options, handoff)` validates the exact
   selected facade and owner candidate, then uses the existing local continuation
   implementation. The public `continue_document` wrapper has no extra option or
   positional argument semantics. Public `map.cut` argument isolation is unchanged.

## Exact carrier admission

The receiving sparse graph is captured by `capture_continuation_document_root`.
Exact adoption derives a `plan_portable_document_subjects` plan using validated
portable names and canonical paths. This adds expected `hson:quad` only to derived
matching data. Canonical Hson nodes and authored attributes are unchanged.

The normal browser matcher checks all carriers together with every other
attribute, node, text boundary, marker, namespace, template-content receiver, and
owner Document. Missing, extra, duplicate, malformed, misplaced, conflicting, and
mixed identity metadata fail before native mutation or stylesheet acceptance.
Every addressed Element has exactly one receiving subject. The normal no-carrier
path and ordinary strict HTML ingress remain unchanged.

Authored names, including underscore-prefixed names, remain registered in the
receiving Library. Disposable names never enter its authored binding tables.
Both kinds of derived HTML carrier are consumed: they are SSR matching evidence,
not permanent DOM identity authority. Authored QUAD lookup continues through the
Library's existing subject association and current path.

## Authority and synchronous realization

Before any DOM write, the handoff prepares the final receiving realization plan,
subject/Element metadata writes, portable and translated CSS, and exact managed
style reference. CSS translation preserves rule keys, declarations, scopes,
layers, specificity, and cascade order. Opaque/unresolved/mixed identity selectors
fail closed; identity-free CSS retains its original state.

After portable exact adoption succeeds, the existing Library stylesheet replace
operation accepts translated CSS. The candidate renews its own aggregate fence
only after proving that this exact CSS acceptance was the sole intervening
transition. The original restoration fence stays stale. Publication reentrancy
changing graph, identities, CSS, registry, or authority rejects without renewing it.

The native transition uses existing mutation-publication protection:

1. Write and verify receiving QUID attributes while portable QUAD CSS still works.
2. Replace and verify text in the original managed style Element.
3. Remove portable carriers while receiving QUID selectors already work.
4. Match the complete prepared receiving plan, including runtime identity
   attributes, and verify the original canonical/DOM mappings.
5. Establish borrowed-root Mirror, interactions, and existing bound document CSS;
   commit exact adoption and release publication protection.

There is no await, scheduled task, layout read, or Promise boundary inside this
transition. Even synchronous native callbacks that force style flush see a
matching subject representation at each switch/removal boundary. MutationObserver
callbacks run after the coherent synchronous transaction. Existing runtime manager
activation is still scheduled after continuation publication; asynchronous fixture
loading and module delivery occur before the handoff.

The managed style remains after authored head content in its existing cascade
position. Subsequent CSS authoring uses the same receiving Library and bound CSS
behavior. LiveTree private/runtime-wide CSS is neither captured nor imported.

## Failure, retry, and lifecycle

Native failure does not undo accepted Library state. Construction cleanup disposes
interactions/CSS binding/Mirror, restores portable carriers first, restores portable
style text next, removes tentative runtime identity attributes, and aborts adoption
links/runtime claims. Original Elements are retained. Publication protection lasts
through rollback and abort. Ineffective writes are detected; rollback errors are
reported as an aggregate failure rather than treated as successful cleanup.

A prepared candidate may retry after a successful native rollback while its
renewed owner fence remains current. An intervening graph, identity, Library,
registry, CSS, or authority transition invalidates it. A successful graft retains
existing Mirror movement, replacement lineage, root-rebase, update, retirement,
disposal, and interaction eligibility behavior. Managed Library rules follow
existing authored CSS semantics: removing a subject removes its matching DOM;
authored rule records remain until their existing owning CSS operation changes
or drops them. This cut adds no automatic rule-retirement policy.

Portable re-export requires a fresh Cut 8D projection and explicit current subject
demand. Local receiver QUID selectors are runtime state; snapshots or a consumed
carrier do not grant durable identity or reusable cross-runtime authority.

## Acceptance and next-cut boundary

`test:document-ssr` includes shared source Node/actual Worker handoff cases.
`test:document-ssr-subjects-browser` bundles source directly and runs real Chrome,
covering scripts-disabled SSR and enabled grafting, original Elements, flush
ordering, carrier/CSS rejection, native rollback/retry, authored/disposable names,
independent receivers, final-only repeated components, and lifecycle operations.
No tracked distribution build is required for these browser checks.

Hosted Locus/Echo incremental correspondence lifetime, alias retention/revocation,
replay/fingerprint changes, asynchronous CSS messages, recovery, and delivery
sequencing remain a separate cut. Component Library CSS collection/transfer and
styled-source composition ownership also remain separate; their existing
fail-closed fence is preserved.
