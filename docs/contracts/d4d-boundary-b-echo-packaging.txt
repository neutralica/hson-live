Original assertion and policy

tests/production-dependency-boundary.acceptance.mts, originally line 249:
  assert.ok(echo.gzip < 42 * 1024,
    `endpoint Echo drifted to ${echo.gzip} gzip bytes`);

This is a strict upper bound of 43,008 bytes, not an exact-size equality.
The candidate exceeded the bound by 302 bytes. Separate preceding assertions
enforce emitted dependency ownership, including actual Part implementation
owners, CSS/document decoding exclusions, LiveMap/Locus families and Node
adapters. Size and dependency correctness are independent properties.

History: 735e4f1c introduced graph checks plus a 24 KiB size guard; 7abd25fa
changed it to 32 KiB; 7a1f482d changed it to 40 KiB with the explicit rationale
that Data admission shares the Hson parser rather than a second codec;
e96558b1 changed it to 42 KiB with authored-attribute changes. Current release
notes also call the earlier 40 KiB bound a budget and document a Part-processing
repair that respected it. Thus the size guard had policy significance, even
though it also detects accidental growth. Repository evidence does not establish
a separate measured product requirement or explicit performance approval for
the precise 42 KiB value. Passing owner checks alone did not waive this guard.

The owner has now explicitly approved the temporary replacement:
  echo.gzip < 90_000
43,008 -> 90,000 bytes; increase in the exclusive ceiling: 46,992 bytes.
This is decimal bytes, not 90 KiB. Equality at 90,000 still fails. It is a
temporary ceiling, not a target. Unexplained growth must still be investigated.
No dependency assertion, hook, separate authoring budget or other size policy
is changed or bypassed.

Source causes and shared-chunk placement

Boundary B's livemap.core.ts imports and calls the existing graph editor's
set_live_path_from_projected, replace_live_path_from_projected and delete_live_path
instead of reconstructing mutation candidates through the removed retained
projected-value planner. This retains their helpers: resolve_parent_node,
replace_live_root_from_projected, write_child_value, write_object_property,
write_array_index, delete_child_value and delete_object_property.
The replacement routines now support root-shape preservation and reuse of an
already-selected previous projection. clone_hson_node's metadata copy also
changes from clone_node to a fresh spread record. All are visible in the
readable emitted-module comparison.

Boundary B's replay correction imports and throws the existing
LiveMapReplayInputError in livemap.core.ts when hosted replay does not produce
one exact authority operation. The class definition itself is unchanged;
its new retained use accounts for the error module's additional 296 bytes.

These are used imports implementing graph authority and exact replay checks,
not redundant imports or a second implementation engine. livemap.editor and
livemap.error were already emitted in the initial shared utility chunk on A.
The public /livemap barrel reexports editor/error bindings while deferred replica
code uses their implementations. esbuild retains the newly used functions in
that existing shared chunk; the endpoint consequently downloads them even
though its finite-operation path does not call those mutation routines.
This packaging consequence is real and explained, not a claim that endpoint
execution intrinsically requires graph mutation. Splitting the existing utility
owners could be a separate packaging optimization, but this gate supplies no
reason to restructure correct production code merely to fit the old ceiling.

Architectural assessment

Both initial closures contain exactly four LiveMap modules: document.path,
path, editor and error; and two Locus modules: error and aggregate.protocol.
No new full LiveMap construction, Locus authority/session/persistence, Schema
compiler/evaluator, Part definition/write/contract processing, DOM/CSS parser,
Mirror, LiveTree or Node adapter owner enters the initial closure.
The existing small part-placeholder vocabulary/scanner is unchanged and is
distinct from the forbidden Part-processing implementation owners.

Metafile output contributions confirm these remain deferred on both trees:
livemap.core, livemap.libraries, livemap.node-admission, exact-node-qualification,
part-definition, part-write, part-contract, validate-canonical-hson,
locus.local-initializer, echo.replica-preparation,
echo.aggregate-semantic-codec.internal and echo.registry.
The unused livemap.facade is not retained. Other implementation owners were
checked against the complete positive-contribution initial module inventory,
not merely the loose module-count limits.

Public Echo still captures options.now synchronously through the dependency-free
capture_plain_instruction helper before its promise returns. Full semantic
session/local-initializer admission remains inside the dynamic replica-preparation
path before composition/attachment. That path still verifies schema evidence,
QUAD/scoped correspondence, CSS, fingerprints and initializer/session digests.
Endpoint finite operations still admit and own action payloads through
admit_echo_action_payload/admit_data_input. None of these source owners changed
in Boundary B or this size-policy update.
